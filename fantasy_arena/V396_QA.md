# v0.396 integration verification

Base: published v0.395, commit 9826f10168a1b093d8ec9e673e61aa646ddb52d4.

## Included changes

1. End-turn intent is acknowledged immediately and belongs to the current match/turn. It waits for engine, battle, overlay, ordinary draw and public draw-burn activity, then advances exactly once. Repeated clicks do not enqueue duplicate turns. New match/cancellation invalidates the old request; a stalled action never forcibly unlocks the engine.
2. Overflow at hand size 10+ consumes the deck card once, leaves the hand unchanged, flies from that player's deck, reveals only that burned card and reuses the existing torn-card visual. The presentation queue is visible from either seat and never invokes deathrattle/rebirth/gameplay death logic.
3. Combat overlays receive explicit calculated ATK/DEF/current-HP snapshots. Later exchanges reuse existing coin outcomes without copying a stale battlefield image. Floating values scale to about 92% of printed stat font and persist for 1.8 seconds. The stored-coin badge moves slightly left and grows one font step.
4. Targeted spell drops on immune, friendly-ineligible, missing, dead or stale targets are rejected before spending. They never redirect to a nearby valid card. The exact valid selected UID is used; existing all-enemy DEF reduction rules remain intact.
5. Area attacks use the attacker/front coin result once, apply each victim's own DEF/protection and commit damage to all victims at one impact. Backline units do not roll new coins or open more duel windows; previously stored coin results are reused. Deaths are grouped and area attacks receive no counterattack.
6. The resting hand is moved down by another 5cqh, preserving card size, the 0.28 hand row, hover/hold detail and drag behavior. Bottom clipping is intentionally allowed by the requested layout change.

No new AI decision rules, sound replacements, asset cleanup or game renaming are included.

## Remaining platform limits

The existing 390px portrait layout has fixed minimum battlefield/hand card sizing that causes overlap and offscreen cards. This release does not redesign that phone layout; the downward offset does not claim portrait-layout completeness. Touch checks use Chromium emulation, not physical devices. Safari and direct human audio listening are not part of this UI/rules verification.
